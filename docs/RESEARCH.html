1️⃣ การเลือกเอนจินดาวน์โหลด

ตัวเลือกรองรับเว็บไซต์ดูแลรักษาหมายเหตุ
yt-dlp ✅ เลือกใช้1,000+ เว็บไซต์Active — release ทุกเดือนไลบรารี Python ฝังได้โดยตรง
youtube-dl (ต้นทาง)~1,000ช้ามากนับจาก 2021ล้าสมัย
gallery-dlเน้นรูปภาพActiveไม่ตรงงานวีดีโอ
พัฒนา scraper เองเว็บละ 1 ชุดโค้ดต้องดูแลเองทุกเว็บบำรุงรักษาไม่ไหว
ข้อสรุป: yt-dlp — รองรับเว็บไซต์มากที่สุด, เป็น Python จึง import yt_dlp ได้เลย, มี progress hooks / format selector / rate limit ในตัว, release ถี่พอจะตามการเปลี่ยนแปลงของแพลตฟอร์ม

สิ่งที่ใช้จาก yt-dlp ในโปรเจกต์นี้:

  • format เช่น bestvideo[height<=720][ext=mp4]+bestaudio[ext=m4a]/best — บังคับ mp4 เล่นได้ทุกเครื่อง
  • progress_hooks — ดึง % / ความเร็ว / ETA ขึ้น GUI
  • ratelimit + concurrent_fragment_downloads — จำกัด/เร่งความเร็ว
  • FFmpegExtractAudio — โหมดแยกเสียง MP3

3️⃣ การจัดการ ffmpeg

วิดีโอคุณภาพสูงมักแยกไฟล์วีดีโอกับเสียง ต้องใช้ ffmpeg รวมกลับ — ทางเลือกที่พิจารณา:

  • ❌ บังคับผู้ใช้ติดตั้ง ffmpeg เอง — ขัดข้อง "ไม่ต้องติดตั้งอะไร"
  • ❌ ดาวน์โหลด ffmpeg ตอน first-run — ซับซ้อน เสี่ยงโดน antivirus
  • ✅ Bundle ผ่านแพ็กเกจ imageio-ffmpeg — copy binary (ffmpeg-win-x86_64 v7.1, ~25 MB) ลง EXE ตอน build ผ่าน binaries ใน .spec

ลำดับค้นหาตอน runtime: imageio_ffmpeg.get_ffmpeg_exe() → ข้าง ๆ EXE → _MEIPASS → PATH

4️⃣ Threading model ของ GUI

[Thread: worker]                     [Thread: UI (main)]
  yt_dlp.extract_info()  --queue-->   root.after(100ms) poll
  progress_hooks เช็ค stop_flag        อัปเดต Treeview/Progressbar
  raise DownloadCancelled เมื่อยกเลิก
  • tkinter ไม่ thread-safe → ทุกอย่างที่แตะ UI ต้องอยู่บน main thread
  • worker สื่อสารผ่าน queue.Queue เท่านั้น
  • การยกเลิก: UI ตั้ง threading.Event → progress hook (บน worker thread) เช็คแล้ว raise DownloadCancelled → yt-dlp หยุดอย่างสะอาด

5️⃣ การแพ็ก EXE ด้วย PyInstaller

  • โหมด onefile + windowed — ไฟล์เดียว ไม่มีหน้าต่างดำ
  • แนบ icon.ico 6 ขนาด (16–256px) + version_info.txt (metadata ของ EXE)
  • ผลทดสอบ: build สำเร็จ, เปิดโปรแกรมได้ (smoke test 6 วินาที), ขนาด ~82.5 MB
  • ข้อแลกเปลี่ยน: onefile แตกไฟล์ลง temp ตอนเปิด (ช้า 2–5 วิแรก) — เปลี่ยนเป็น onedir ได้จาก .spec เดิม

6️⃣ การกระจายไฟล์ (Distribution)

ช่องทางข้อดีข้อเสีย
GitHub Releases + Actions ✅ เลือกใช้ฟรี build อัตโนมัติจาก tag มี SHA256SmartScreen ยังเตือน (ไม่มี code signing)
Code signing certไม่มีเตือน~$100–400/ปี
Microsoft Storeการรับรองจาก MSค่าธรรมเนียม + review

GitHub Actions (release.yml): push tag v* → ติดตั้ง Python + deps → build ด้วย .spec เดียวกับ local → คำนวณ SHA256 → สร้าง release พร้อมแนบ EXE และ checksums.txt

GitHub Pages: หน้าเว็บสถิติ (ไม่มี build step) ดึง api.github.com/repos/.../releases/latest แล้วแสดงเวอร์ชัน วันที่ ขนาดไฟล์ ปุ่มดาวน์โหลด และ SHA256 จาก checksums.txt — checksum บนหน้าเว็บจึงตรงกับไฟล์จริงเสมอ เพราะมาจาก release เดียวกัน (มี cache ใน localStorage 1 ชม. กันโดน API rate limit)

7️⃣ ความเสี่ยงและการรับมือ

ความเสี่ยงระดับการรับมือ
เว็บไซต์เปลี่ยนโครงสร้าง → ดาวน์โหลดพังสูงอัปเดต yt-dlp บ่อย + CI build จาก tag ใหม่ง่าย
SmartScreen เตือนผู้ใช้ใหม่กลางเอกสาร "Run anyway" + เผยแพร่ SHA256 ให้ตรวจ
การใช้งานผิดกฎหมายกลางข้อความ Legal ชัดเจน ไม่ใส่ฟีเจอร์เจาะจงเว็บผิดกฎหมาย
API rate limit บนหน้าเว็บต่ำcache localStorage 1 ชม. + fallback ลิงก์ Releases
Python 3.14 ใหม่มากต่ำทดสอบ build ผ่านแล้ว, CI pin 3.13 สำรอง
